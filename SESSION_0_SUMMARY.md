## Key Design Decisions

### 1. **Four Layers (Never Collapse)**

All UI and data must preserve boundaries:

```
PRIMARY SOURCE (Bruno's words)
  ↓ extraction
SCHOLARLY INTERPRETATION (what scholars claim)
  ↓ parsing
RECONSTRUCTION (operationalized techniques)
  ↓ labeling (HISTORICALLY_ATTESTED | DIRECT | SCHOLARLY | SPECULATIVE)
EXPERIMENT (interactive tools)
```

### 2. **Provenance-Tracked**

Every claim traces back:
- Passage → Source file → Edition → Author
- Technique → Evidence passages → Bruno's own words
- Scholar disagreement → Both positions with evidence

### 3. **Scholar Modes (Not Scholar Filters)**

Users don't filter by scholar preference. Instead, they **switch interpretive frameworks**:

- **BRUNO THROUGH YATES** — Hermetic, talismanic, cosmic
- **BRUNO THROUGH CLUCAS** — Plotinian, ethical, soul-ordering
- **BRUNO THROUGH MERTENS** — Spirit-regulating, transformative
- **BRUNO THROUGH WANG** — Iconic practice, gnoseological
- **BRUNO THROUGH BARENSTEIN** — Cognitive, non-esoteric
- **BRUNO THROUGH COULIANO** — Psychological bonds, desire

When switched, the same image/technique/concept appears differently—because interpretation changes function.

### 4. **SQLite + FTS5 + Python (No Heavy APIs)**

- Local-first (no CloudFlare, no OpenAI API cost)
- Rerunnable ingestion pipeline (incremental, safe)
- FTS5 for fuzzy search (mirrors, NEAR(), prefix matching)
- Simple schema (easy to reason about, modify, extend)

### 5. **Card Reuse Strategy**

Rather than rebuild from scratch, adapt existing portal components:
- Biography cards (from WITCHER PORTAL)
- Concept cards (from IslamicateOccultPortal)
- Dispute cards (novel, but styled consistently)
- Work/edition cards (adapted from TurkaGame)

### 6. **Unresolved Questions as Features**

Rather than resolve scholarly debates, surface them:
- "How magical is Bruno's ars memoriae?" → CONTESTED
- "What exactly does an image do?" → OPEN
- "Can we transcend the magic/science binary?" → DEVELOPING

Users can explore all positions simultaneously.
